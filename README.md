# 호돈 윷놀이 v10 — 강퇴·관전·팀 공용 말·윷 결과 처리 수정판

기존 v9 화면과 호돈 얼굴 말/윷 결과 이펙트/우승 폭죽 연출을 유지하면서 방 관리와 팀전 규칙, 결과 대기열 처리를 수정했습니다.

## v10 변경 사항

### 방 관리
- 방장이 다른 플레이어를 강퇴할 수 있습니다. 진행 중인 게임에서도 강퇴 가능하며, 강퇴된 사람이 차례 중이면 남은 결과를 정리하고 다음 참가자에게 넘깁니다.
- 관전자로 입장할 수 있습니다. 관전자는 윷 던지기/말 이동/게임 시작을 할 수 없고 실시간 게임 화면만 볼 수 있습니다.
- 방장은 관전자도 강퇴할 수 있습니다.
- 관전자 토큰은 서버 내부에만 보관하고 다른 참가자에게 노출하지 않습니다.

### 팀전
- 2대2 팀전은 청팀(1·3번)이 공용 말 3개를 함께 사용하고, 홍팀(2·4번)도 공용 말 3개를 함께 사용합니다.
- 팀원이 같은 칸에 도착하면 함께 업힙니다.
- 같은 팀 말은 잡히지 않습니다. 팀원 말을 잡는 별도 선택지도 제거했습니다.
- 상대 팀 말을 잡으면 추가 던지기 1회를 받습니다.
- 팀 공용 말 3개를 모두 완주하면 해당 팀이 승리합니다.

### 윷 결과/차례 오류
- 던진 결과는 순서대로 대기열에 보관합니다.
- 앞선 결과가 말을 출발시킬 수 있으므로, 아직 말이 출발하지 않았다는 이유로 뒤에 대기 중인 빽도를 미리 버리지 않습니다.
- 앞선 윷 결과를 이동한 다음 빽도 가능 여부를 다시 판정합니다.
- 대기열 맨 앞의 빽도를 실제로 이동할 말이 없을 때만 해당 빽도를 소멸시킵니다.
- 상대 말을 잡으면 결과 대기열이 남아 있더라도 추가 던지기 권한을 보존합니다.

## 설치: GitHub → Bonto
1. ZIP 압축을 풀고 `HODON-YUT-v10-Bonto` 폴더 안의 파일을 사용합니다.
2. `app.js`, `game.js`, `game.test.js`, `index.html`, `server.js`, `style.css`, `package.json`, `render.yaml`, `hodon-face.png`를 GitHub 저장소 최상위에 업로드해 기존 파일과 교체합니다. 폴더 안에 다시 넣지 않습니다.
3. GitHub에서 변경된 파일을 커밋합니다.
4. Bonto가 GitHub 변경사항을 자동 반영하지 않으면 Bonto 편집기에서 같은 파일을 교체하거나 저장소를 다시 가져옵니다.
5. Bonto에서 Save → Restart를 실행합니다.
6. 게임을 열고 Mac Chrome에서 `Command + Shift + R`로 강력 새로고침합니다.
7. 상단에 `온라인 · v10`이 표시되는지 확인합니다.

## 검증 결과
- JavaScript 구문 검사: `server.js`, `app.js`, `game.js` 통과
- 자동 게임 규칙 테스트: 16개 통과
- 빽도 대기열 시뮬레이션: 대기 말만 있을 때 `윷 → 빽도` 순서로 결과를 보존하고, 윷 이동 후 빽도를 정상 실행하는 케이스 통과
- 팀 공용 말/팀원 비포획/상대 포획 추가 던지기/강퇴 후 차례 건너뛰기 규칙 테스트 통과
- 이 실행 환경에는 Express/Socket.IO 의존성이 설치되어 있지 않아 실제 호스팅 서버에 연결한 실시간 브라우저 테스트는 수행하지 못했습니다. Bonto 배포 후 2~4개 브라우저로 최종 확인이 필요합니다.

## 주의
- 서버 재시작 시 현재 진행 중인 방/게임은 메모리에서 초기화됩니다.
- 기존 `field-records.json`이 있다면 배포 전에 백업하세요.
- 팀전 규칙은 기존의 팀원별 3개(팀당 6개)에서 팀 공용 3개로 바뀝니다.
